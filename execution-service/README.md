# execution-service

Spring Boot service that runs user code in isolated Docker containers.

- **Port:** `8082` (T-06 section 1)
- **Health:** `GET /actuator/health`
- **Run:** `POST /v1/runs` — see [docs/api-contracts.md](../docs/api-contracts.md) section 4

> **Sprint 1 / US-08 status (Jay Limbasiya):**
> The run endpoint calls **FakeCodeRunner** — a deterministic in-process stub.
> No Docker is involved. Quincy's PR (`feature/US-08-run-code-runner-hookup`) swaps
> in the real DockerCodeRunner (US-09) once that branch merges.

## Run endpoint

```
POST http://localhost:8082/v1/runs
Content-Type: application/json
```

### Request fields (T-06 §4.1)

| Field        | Type          | Required | Notes                                              |
|--------------|---------------|----------|----------------------------------------------------|
| `request_id` | string (UUID) | Yes      | Generated by the client; echoed in the response.   |
| `room_id`    | string        | Yes      | Room the result is broadcast to (FR4.5).           |
| `session_id` | string (UUID) | Yes      | Stable browser session id (T-06 §3.3).             |
| `language`   | string        | Yes      | One of: `cpp`, `python`, `c`, `java`, `javascript` |
| `code`       | string        | Yes      | Source code to run (FR4.1).                        |
| `stdin`      | string        | No       | Standard input; defaults to `""` (FR4.1).          |

### Response fields (T-06 §4.2)

All fields are always present — including on compile errors, timeouts and OOM (FR4.2).

| Field               | Type          | Notes                                                              |
|---------------------|---------------|--------------------------------------------------------------------|
| `request_id`        | string        | Echoed from the request.                                           |
| `room_id`           | string        | Echoed from the request.                                           |
| `language`          | string        | Echoed from the request.                                           |
| `stdout`            | string        | Always present, may be `""`.                                       |
| `stderr`            | string        | Always present, may be `""`.                                       |
| `exit_code`         | integer       | Process exit code (FR4.4).                                         |
| `execution_time_ms` | number        | Wall-clock milliseconds (FR4.3, FR6).                              |
| `peak_memory_mb`    | number        | Peak memory in MB (FR4.3, FR6).                                    |
| `timed_out`         | boolean       | `true` if killed by wall-time limit (NFR4.1).                      |
| `oom_killed`        | boolean       | `true` if killed by memory limit (NFR4.2).                         |
| `failure_kind`      | string / null | `"compile_error"`, `"non_zero_exit"`, `"timeout"`, or `null`.      |
| `output_truncated`  | boolean       | `true` if output was cut at the cap (NFR4.4).                      |
| `message`           | string / null | Short UI sentence, e.g. `"Time limit exceeded"`. `null` otherwise. |

### Room delivery (FR4.5, T-06 §5)

After execution finishes, execution-service POSTs a `run-result` message to sync-service's
internal endpoint. sync-service forwards it as a WebSocket text frame to every connection in
the room — including the client that pressed Run. This is best-effort: if sync-service is
down the endpoint still returns HTTP 200 to the caller.

```
POST {SYNC_SERVICE_INTERNAL_URL}/internal/rooms/{room_id}/messages
X-Internal-Token: <INTERNAL_API_TOKEN>
```

### Supported languages (DR1)

`cpp` · `python` · `c` · `java` · `javascript`

First language working end-to-end is recorded in T-14.

## How to run locally

```bash
cd execution-service

# Run all tests
mvnw.cmd -B verify          # Windows (uses wrapper from .m2 cache)
./mvnw -B verify            # Linux / macOS

# Start the service (stays running on port 8082)
mvnw.cmd spring-boot:run
```

### Environment variables

Copy `.env.example` to `.env` and fill in your local values.
**Never commit `.env` or `INTERNAL_API_TOKEN`.**

| Variable                  | Default                    | Purpose                                         |
|---------------------------|----------------------------|-------------------------------------------------|
| `CLIENT_ORIGIN`           | `http://localhost:3000`    | CORS origin allowed (T-06 §2).                  |
| `SYNC_SERVICE_INTERNAL_URL` | `http://localhost:8081`  | Where to broadcast run results (T-06 §5).       |
| `INTERNAL_API_TOKEN`      | *(must be set)*            | Shared secret for sync-service internal endpoint. |

## How to verify (curl)

> Port `8082`, path `/v1/runs`. Python is used as the first example language (T-14).

```bash
# 1. Health – expected: 200 {"status":"UP"}
curl -i http://localhost:8082/actuator/health

# 2. Success run – expected: stdout "Hello from python!\n", stderr "", exit 0
curl -s -X POST http://localhost:8082/v1/runs \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "0b9d2f3e-7a41-4c58-9e1b-5d3c8a6f2e10",
    "room_id":    "room-demo-01",
    "session_id": "7c1e4a52-3b0d-4f6a-9a2e-8d5f1b6c3e90",
    "language":   "python",
    "code":       "print(\"hello\")",
    "stdin":      ""
  }'

# 3. Failure run – expected: stderr "boom\n", exit 2, failure_kind "non_zero_exit"
curl -s -X POST http://localhost:8082/v1/runs \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "1a2b3c4d-0000-4000-aaaa-000000000001",
    "room_id":    "room-demo-01",
    "session_id": "7c1e4a52-3b0d-4f6a-9a2e-8d5f1b6c3e90",
    "language":   "python",
    "code":       "import sys; sys.stderr.write(\"boom\"); sys.exit(2)"
  }'

# 4. Stdin run – expected: stdout "ABC\n"
curl -s -X POST http://localhost:8082/v1/runs \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "1a2b3c4d-0000-4000-aaaa-000000000002",
    "room_id":    "room-demo-01",
    "session_id": "7c1e4a52-3b0d-4f6a-9a2e-8d5f1b6c3e90",
    "language":   "python",
    "code":       "print(input().upper())",
    "stdin":      "abc"
  }'

# 5. Missing 'code' – expected: 400 INVALID_REQUEST
curl -i -X POST http://localhost:8082/v1/runs \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "0b9d2f3e-7a41-4c58-9e1b-5d3c8a6f2e10",
    "room_id":    "room-demo-01",
    "session_id": "7c1e4a52-3b0d-4f6a-9a2e-8d5f1b6c3e90",
    "language":   "java"
  }'

# 6. Unsupported language – expected: 422 UNSUPPORTED_LANGUAGE
curl -i -X POST http://localhost:8082/v1/runs \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "0b9d2f3e-7a41-4c58-9e1b-5d3c8a6f2e10",
    "room_id":    "room-demo-01",
    "session_id": "7c1e4a52-3b0d-4f6a-9a2e-8d5f1b6c3e90",
    "language":   "ruby",
    "code":       "puts \"hi\""
  }'
```

## Resource limits (DR3)

Limits are read from `src/main/resources/application.yml` under `app.execution.limits`.
They are **never hard-coded** in Java source. Current values are placeholders;
Sprint 2 sets real limits (NFR4).

| Key                   | Placeholder | Notes                                    |
|-----------------------|-------------|------------------------------------------|
| `wall-time-seconds`   | 5           | NFR4.1 – killed after this many seconds  |
| `memory-mb`           | 128         | NFR4.2 – container memory cap            |
| `pids-limit`          | 64          | NFR4.3 – max processes inside container  |
| `max-output-bytes`    | 1 048 576   | NFR4.4 – 1 MiB stdout+stderr cap        |
| `max-request-body-bytes` | 1 048 576 | T-06 §2 – request body cap             |
