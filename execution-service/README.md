# execution-service

Spring Boot service that runs user code in isolated Docker containers.

- **Port:** `8082` (T-06 section 1)
- **Health:** `GET /actuator/health`
- **Run:** `POST /v1/runs` — see [docs/api-contracts.md](../docs/api-contracts.md) sections 4, V2.8 (Decision 8) & V2.9 (Decision 9)

> **Sprint 2 / T-19 status (Jay Limbasiya & Yash Oza):**
> The run endpoint consumes the unified **RunSpec** object (Decision 8) and returns
> enriched execution results with Decision 9 fields (`runner`, `ran_at`, `visibility`,
> `saved_versions`, `failure`, `compile_time_ms`).
> Calls **FakeCodeRunner** — a deterministic in-process stub until the Docker runner (PR #40) lands.
> Gated by **RunQueueGate** (US-11) for concurrency limiting.

## Run endpoint

```
POST http://localhost:8082/v1/runs
Content-Type: application/json
```

### Request fields (T-17 V2.8 / Decision 8)

| Field        | Type          | Required | Notes                                                                   |
|--------------|---------------|----------|-------------------------------------------------------------------------|
| `request_id` | string (UUID) | Yes      | Generated by the client (UUID v4); echoed in the response.              |
| `room_id`    | string        | Yes      | Room the result is broadcast to (FR4.5).                                |
| `session_id` | string (UUID) | Yes      | Stable browser session id (UUID v4, T-06 §3.3).                         |
| `language`   | string        | Yes      | One of: `cpp`, `python`, `c`, `java`, `javascript`                      |
| `stdin`      | string        | No       | Standard input; defaults to `""` (FR4.1).                               |
| `source`     | object        | Yes      | Spec object defining files or saved snapshot to execute (Decision 8).   |

> **Legacy field:** A body containing `code` is rejected with HTTP `422 INVALID_REQUEST`.

### Three source shapes

1. **Pair mode (inline source):**
   ```json
   {
     "kind": "inline",
     "files": [
       { "name": "main.py", "content": "print(\"hello\")" }
     ],
     "entry": "main.py"
   }
   ```
2. **Open mode (one runnable module):**
   ```json
   {
     "kind": "saved",
     "target": "module",
     "module_id": "mod_9Qx7mBvA2nR0"
   }
   ```
3. **Open mode (through entry file):**
   ```json
   {
     "kind": "saved",
     "target": "entry",
     "module_ids": "all"
   }
   ```
   *(or `"module_ids": ["mod_1", "mod_2"]`)*

### Response fields (T-17 V2.9 / Decision 9)

All fields are always present — including on compile errors, timeouts and OOM (FR4.2).

| Field               | Type                  | Notes                                                              |
|---------------------|-----------------------|--------------------------------------------------------------------|
| `request_id`        | string                | Echoed from the request.                                           |
| `room_id`           | string                | Echoed from the request.                                           |
| `language`          | string                | Echoed from the request.                                           |
| `stdout`            | string                | Always present, may be `""`.                                       |
| `stderr`            | string                | Always present, may be `""`.                                       |
| `exit_code`         | integer               | Process exit code (FR4.4).                                         |
| `execution_time_ms` | number                | Wall-clock milliseconds for the run stage only (FR4.3, FR6).        |
| `peak_memory_mb`    | number                | Peak memory in MB (FR4.3, FR6).                                    |
| `timed_out`         | boolean               | `true` if killed by wall-time limit (NFR4.1).                      |
| `oom_killed`        | boolean               | `true` if killed by memory limit (NFR4.2).                         |
| `failure_kind`      | string / null         | `"compile_error"`, `"non_zero_exit"`, `"timeout"`, or `null`. An OOM kill is always `"non_zero_exit"` with `oom_killed: true` (never `"oom"`). |
| `output_truncated`  | boolean               | `true` if output was cut at the cap (NFR4.4) or 4 MiB frame limit. |
| `message`           | string / null         | Short UI sentence, e.g. `"Time limit exceeded"`. `null` otherwise. |
| `compile_time_ms`   | number / null         | Compile stage time in ms; `null` for languages without compile stage. |
| `runner`            | object                | `{ "member_id": "...", "display_name": "..." }` (Decision 9).      |
| `ran_at`            | string (ISO-8601 UTC) | Timestamp when execution started (`uuuu-MM-dd'T'HH:mm:ss.SSS'Z'`). |
| `visibility`        | string                | `"room"` in Pair mode; `"private"` in Open mode (Decision 10).     |
| `saved_versions`    | array of objects      | Open mode: list of `{ module_id, name, version, saved_by, saved_at }`. `[]` in Pair mode. |
| `failure`           | object / null         | Open mode: `{ module_id, name, owner, last_saved_by }` if failed and pinned to a module; `null` otherwise. |

### Room delivery & audience (FR4.5, T-06 §5, Decision 10)

After execution finishes, execution-service broadcasts the run result to sync-service:
- In **Pair mode**, broadcast with audience `{"kind":"room"}`.
- In **Open mode**, broadcast with targeted session audience `{"kind":"sessions","session_ids":[sessionId]}` (visibility `private`).

- Java 21 (Temurin recommended)
- Maven 3.9+ **or** use the Maven Wrapper (`./mvnw` or `mvnw.cmd`)

## How to run locally

```bash
cd execution-service

# Run all tests
mvnw.cmd test               # Windows
./mvnw test                 # Linux / macOS

# Start the service (port 8082)
mvnw.cmd spring-boot:run
```

### Environment variables

Copy `.env.example` to `.env` and fill in your local values.
**Never commit `.env` or `INTERNAL_API_TOKEN`.**

| Variable                    | Default                 | Purpose                                           |
|-----------------------------|-------------------------|---------------------------------------------------|
| `CLIENT_ORIGIN`             | `http://localhost:3000` | CORS origin allowed (T-06 §2).                    |
| `SYNC_SERVICE_INTERNAL_URL` | `http://localhost:8081` | Where to broadcast run results (T-06 §5).         |
| `INTERNAL_API_TOKEN`        | *(must be set)*         | Shared secret for sync-service internal endpoint. |

```bash

curl -i http://localhost:8082/actuator/health

# 2. Pair mode success (inline source)

  -H "Content-Type: application/json" \

    "room_id":    "room-demo-01",

      "kind": "inline",

      "entry": "main.py"
    }
  }'

# 3. Open mode success (saved module snapshot)
curl -s -X POST http://localhost:8082/v1/runs \
```

## Resource limits (DR3)

Limits are read from `src/main/resources/application.yml` under `app.execution.limits`.
They are **never hard-coded** in Java source.

| Key                      | Value       | Notes                                    |
|--------------------------|-------------|------------------------------------------|
| `wall-time-seconds`      | 5           | NFR4.1 – killed after this many seconds  |
| `memory-mb`              | 128         | NFR4.2 – container memory cap            |
| `pids-limit`             | 64          | NFR4.3 – max processes inside container  |
| `max-output-bytes`       | 1 048 576   | NFR4.4 – 1 MiB stdout+stderr cap         |
| `max-request-body-bytes` | 1 048 576   | T-06 §2 – request body cap               |
| `max-queue-length`       | 8           | FR16 – concurrent/waiting run limit      |
| `queue-retry-after-seconds` | 5        | FR16 – retry hint on 503 QUEUE_FULL      |
